# tools/ —— 侦察与排查小工具

这些脚本**不是**日常跑任务用的，是「摸界面 / 查故障」时的一次性工具。
留在这里是因为它们记录了界面结构是怎么被摸出来的 —— 游戏改版后还要靠同类脚本重新采一遍。

> 日常使用请走项目根目录的 `config_tool.bat` / `run_now.bat` / `run_daily.bat`。

---

## 日常会用到的

| 脚本 | 干什么 |
|---|---|
| `selftest.py` | **离线自检（420 项断言）**。改完代码必跑，必须全绿 |
| `config.py` | 本机配置工具，跟 `config_tool.bat` 是同一个东西（菜单 + 命令行） |
| `emu.py` | 手动开关模拟器：`status` / `start` / `stop` / `kill` / `restart` / `game-stop` |

## 看屏幕用的小工具

| 脚本 | 干什么 |
|---|---|
| `look.py` | 截一张图 + OCR，直接把屏幕上的文字和坐标打出来（最常用的排查手段） |
| `ocr_probe.py` | 对已有截图跑 OCR，调阈值/别名表时用 |
| `probe_ocr_panel.py` | **面板判定出问题时先跑它**：对截图跑「原图 OCR vs 放大 2x OCR」，一眼看出是「面板真没打开」还是「OCR 整屏漏读」。2026-09-20 税收任务「进不去」就是靠它定位的（39 帧里 17 帧漏读） |
| `seq.py` | 按脚本连续执行一串动作（点按序列），复现某个界面 |
| `nav.py` | 单独调试导航（进面板 / 退回来） |

## 账号 / 角色切换的侦察（这一组是这次新增的）

切换逻辑（`stzb/account.py`）里的所有坐标都来自这几次实测，
**不是猜的**。游戏改版后照这个顺序重采：

| 脚本 | 那次侦察解决/发现了什么 |
|---|---|
| `probe_account.py` | 第一版：只「看」不点，把当前界面的 OCR 全打出来，先搞清账号/角色入口在哪 |
| `probe_login.py` | 冷启动 → 登录页 → 主城，把沿途每个界面的文字全打出来 |
| `probe_switch.py` | 第一版切换侦察（**失败**）：在登录页按了返回键 → 弹出「中途退出」问卷，把整屏盖住，白探 8 次 |
| `probe_switch2.py` | 修正版：**登录页绝不用返回键**，只用面板自己的 ✕ / 确定。踩坑记在文件头 |
| `probe_switch3.py` | 定位到「用户中心 → 切换账号」这条链路，以及「点击换区 → 选择服务器」 |
| `probe_switch4.py` | **终版，有效坐标出自这里**：左上角图标 (60,62) → 用户中心；「切换账号」(1566,288)；用户中心 ✕ 是 **(1671,156)**（不是 1760，实测偏了 90px）；「点击换区」(1100,759) |

证物在 `recon/switch4.json`（OCR 的每一行文字 + 坐标），
`tests/test_account.py` 就是拿它当输入的。

### 踩过的两个坑（别再踩）

1. **必须一次性跑完。** 本机环境下模拟器挂在发起命令的进程树上，
   命令一结束整棵树被回收（表现为「刚报就绪，再查就 `is_process_started=False`」）。
   所以「启动 → 等就绪 → 截图 → OCR → 打印」必须在**同一个进程**里完成。
   `tools/detach_emu.py` 是另一种解法：用 `DETACHED_PROCESS` 起 MuMu，让它挂到系统上。
2. **登录页上绝不能按 Android 返回键**（`keyevent 4`）——
   会弹出「请问，导致中途退出的原因是？」问卷，下面就是**「提交并退出」**。
   退出面板只用面板自己的 ✕ / 确定 / 「继续游戏」。
